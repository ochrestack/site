Rigbake quick start

Installing Rigbake and your first export. The full manual, README.md, is inside the download, and so is this page, as docs/quick-start.md. Back to the Rigbake product page.

Install (Blender 4.2 or later)

  1. Download rigbake-1.3.0.zip. Do not unzip it.
  2. In Blender, open Edit > Preferences > Get Extensions.
    • Blender may first ask about internet access, with Continue Offline and Allow Online Access. Rigbake needs no internet, so Continue Offline is fine.
    • Blender may then show a "Repository Alert" saying that the remote data of extensions.blender.org is unavailable. That message comes from Blender's online repository, not from Rigbake. You can ignore it.
  3. Open the drop-down menu (⌄) at the top right, choose Install from Disk... and pick the zip. The status bar says Installed "rigbake". Dragging the zip onto the Blender window also works.
  4. Press N in the 3D Viewport and open the Rigbake tab.

To update, install the newer zip the same way. To remove Rigbake, go to Preferences > Add-ons, find Rigbake, and choose Uninstall from its drop-down menu.

First export

  1. In Object Mode, select the armature that deforms your mesh. With a control rig, select the deform (game) rig; Rigbake finds the control rig.
  2. Click Validate Rig for Export. A dialog lists the issues first, then notes (things Rigbake handles for you, such as constraints it bakes). It stays open until you close it; Open Full Report opens the whole report in a Text Editor window. The panel keeps the counts, with a Report button.
  3. Pick the Preset (Godot, Unity or Unreal) and the Folder. Below the File Name, the panel shows the file it will write and the clips it will export, for example "2 clips: Walk, Run (from CTRL)". If it says "Save the .blend file first", save, or pick an absolute folder.
  4. Click Export Game-Ready. The status bar says, for example, "Exported 2 clips to DEF.glb." The Last Export box below the button lists every clip with its frame range and every warning, and its folder button opens the export folder.

Every action that is the armature's active action or sits on its NLA (stashed ones included) becomes its own clip, or every such action of the control rig. An action that is neither, for example one kept only by its fake user, is not exported: the panel names it under the Export button, and Add to NLA stashes it so the next export includes it.

Export Game-Ready bakes for you. Advanced Bake (closed by default) has the bake settings: Actions, Frame Range, Clips From, Keep Hand-Edited Bakes and Bake Before Export, and a button to bake without exporting.

Each clip is baked from the rest pose. If a warning says a clip "does not key" some bones that are posed in the viewport, the file shows those bones at rest, while the viewport still shows them where another clip or your hands left them.

Importing into Godot

The exported files are exact: re-imported into Blender, every bone is within 1e-5 m of the live rig. Two Godot import settings decide how exactly Godot plays them:

  • Animation > FPS (Import dock, default 30): set it to your Blender frame rate (Scene Properties > Format > Frame Rate). Godot re-samples every clip at this rate.
  • Optimizer of the AnimationPlayer (Import dock > Advanced... > select the AnimationPlayer node): on by default. It drops keys it judges redundant, which on fast motion put bones up to 13 cm off on our test rigs. Turn it off where you need the exact motion.

Click Reimport after changing them. With both set, every bone matched Blender within 0.0002 m in our check.

Limits

  • Checked in Godot 4.7 and in a real Blender 4.2 LTS window. The Unity preset's FBX was checked through Godot's FBX importer. The Unreal preset has not been checked in Unreal Engine. Neither has been opened in Unity or Unreal.
  • Only bone motion is baked. Shape keys and their animation are exported as they are (Godot preset), or dropped with a warning (FBX presets, when the mesh has other modifiers). Custom properties and B-Bone properties are not baked. Keys are baked on whole frames.
  • Motion keyed on the armature object itself is not exported; the validator and the export warn about it.
  • One control rig per deform rig. One file per export.

Privacy

Rigbake makes no network connections and sends nothing anywhere.
