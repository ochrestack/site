Attachkeep quick start

Your first scan and your first clean-up, step by step. Back to the Attachkeep product page.

Install (Confluence Cloud)

  1. In Confluence, open Apps > Explore more apps, search for Attachkeep (once the listing is live), and choose Get app.
  2. A site administrator approves the permissions. Each one is explained on the product page.
  3. Open Confluence settings (the gear) > Attachment cleanup, in the Apps section of the sidebar.

Only Confluence administrators can use the page. Everyone else, space administrators included, sees an explanation that a Confluence administrator is needed.

Before the first scan: protect what must stay

Open the Settings tab. Set the protected label (keep unless you change it) and choose any excluded spaces. Files carrying the label, and every file in an excluded space, are listed but can't be selected or deleted. Runs always use the current settings; re-run the scan to update the list's markings.

1. Scan the site

On the Attachments tab, choose Scan the site. The scan runs in the background and changes nothing. A progress bar shows the phase and how many attachments, pages, blog posts and comments it has read. You can leave the page and come back; Stop ends the scan, and Re-run scan refreshes the list any time.

2. Read the storage summary

When the scan finishes, the Storage table shows each space's files and megabytes and how much of it is unused, with the site total at the bottom. "MB" means a million bytes, and only the current version of each file is counted.

3. Filter

  • Tick Unused only for the files nothing on the site refers to.
  • Tick Uploader no longer active for files uploaded by deactivated or closed accounts.
  • Narrow by space, file type, minimum size or uploaded before a date, or search by file, page or uploader.

The list is sorted by size, largest first. Download CSV saves every file your filters show, with all the columns and the reason, for a spreadsheet. The Why column says what keeps each file in use, or that nothing does:

StatusExample reason
In usereferenced from the page "Design review"
In usereferenced from a comment on "Release 4.2 notes"
In useshown by the Attachments macro on its own page
In usenamed by a macro on "System overview" (a diagram)
Unusedno page, blog post or comment on the site references this file
On an archived pagelisted apart; not counted as unused
Not checkedthe app can't read its page or its properties (for example, restrictions that exclude apps); never unused

4. Select

Tick rows, or choose Select all matching to take everything your filters show, up to 1,000 files a run. Protected files and files in excluded spaces have a disabled checkbox and the reason in the Why column.

5. Preview and dry run

Preview delete… shows the number of files, the megabytes and the list. It warns if a selected file is in use, and lists any file it left out and why. Choose Run dry run.

The dry run checks every file again: it still exists, it is still on the same page, it is still unused if you selected it as unused, and it isn't protected. The result shows how many files would move and how many would be skipped, and why. For example, a file someone linked since the scan shows it is in use now with the page that uses it, such as it is in use now: referenced from a comment on "Production architecture". Nothing has changed yet.

6. Delete for real

Choose Delete these N files for real…, tick I understand: N files will be moved to the space trash, and confirm. The run moves each file to its space trash in the background. One failure never stops the others. It ends with a summary: files moved, megabytes, and each failure with Confluence's reason. Download CSV under the summary saves every file of the run with its result and reason, a record you can attach to a change ticket.

7. Restore a file, if you need to

Open the Activity tab. For a delete run, Files moved lists each file with a link to its page, and CSV saves the run's files with their results. To bring one back, open that space's trash (Space settings > Trash) and choose Restore. Attachkeep never empties the trash; that stays with the space administrators.

Limits

  • Confluence Cloud only. English only.
  • Drafts are not cleaned up. Links to a file from outside Confluence (email, Jira issues, other websites, bookmarks) can't be seen, so such a file looks unused.
  • Pages whose restrictions exclude apps aren't read: their files are "Not checked", but a link from such a page to a file on another page can't be seen.
  • Macros are matched by name: any macro parameter that equals a file's name keeps that file, so a panel titled "Roadmap" also keeps "Roadmap.png".
  • Whiteboards, databases and custom content are not scanned. No purge, no old versions, at most 1,000 files per delete run.
  • A file moved to another page after the scan is skipped with "it has moved to another page since the scan; run the scan again".

Privacy

Attachkeep runs on Atlassian Forge, calls only your site's Confluence API and sends nothing anywhere else: no analytics, no telemetry. Forge storage holds only the activity log and settings.

Support
