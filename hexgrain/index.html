Hexgrain: Debugger Hex View

In the IntelliJ IDEA debugger, a byte[] is a column of signed decimals, 100 at a time. Reading a header means scrolling, converting and counting. Hexgrain shows it as a hex dump.

  • Read it like a hex editor: 8, 16 or 32 bytes a row, the characters beside them.
  • See what the last step changed: changed bytes are marked at every pause.
  • Big arrays, no drilling into indices: Go to offset, Find, a data inspector, Save (licence).

In the IDE, for real

How these images were made

IntelliJ IDEA 2025.3 (IU-253.28294.334), started with ./gradlew runIde from Hexgrain 1.0.1 under a virtual display at 1280×800, dark theme, driven with real clicks and keys. The project is metadata-extractor (Apache-2.0) at commit 4d5cd469. The PNG is its test file photoshop-8x12-rgb24-all-metadata.png, the JPEG its test file nikonMakernoteType2b.jpg. The added program overwrites xmp:ModifyDate and xmp:MetadataDate and recomputes the chunk's CRC; an independent check of the same edit counts the same 24 changed bytes. The listing does not exist yet, so the images with licensed features were taken with a stand-in for JetBrains Marketplace licensing in that sandbox IDE, and the free-tier images with the same stand-in set to "no licence".

Known limits

  • Java and Kotlin in IntelliJ IDEA only: not Rider, Python, Go, JavaScript, C, C++, Rust, Remote Development or Android Studio.
  • Change marks cover the whole array up to 1 MiB; above that, the rows read at both pauses.
  • Read-only. A direct ByteBuffer is read through a copy in the program's heap.
  • Arrays larger than 1 GiB have not been measured.
Measured speed, and more questions

Measured. On a 1 GiB byte[], every recorded run: first rows within 85 ms, Go to in 1 to 2 ms (median). A Find through all of it with no match: 38 to 53 seconds.

Does it slow down debugging? It reads only while a Hex tab is open and the program is paused, and after Resume it reads nothing until the next pause. Arrays and heap buffers are read directly, without running program code. A Save of a large array holds the pause until it is written (about 5 seconds per 128 MiB).

A called method has its own variable with the same name. The tab keeps showing the array you opened, read at this pause, with a line naming the other method. If your variable is given a new array, the tab shows the new one, says so, and marks nothing. Re-reads follow variables, fields, casts and numeric indexes; an expression with method calls is not run again, and the tab says so.

When the trial ends each licensed control shows one line with the price and a link to the IDE's licence dialog. No pop-up, banner or notification; the free hex dump keeps working.

Rider and C#? Not yet. Hexgrain has not been run in a real Rider debug session, so it declares itself incompatible with Rider, and Rider will not install it. Other JetBrains IDEs can install it but have nothing for it to show. Attaching to a JVM on another machine has not been tested.
