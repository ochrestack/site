Hedroot: Header/Source Folders

CLion's New | C++ Class writes the header and the source into the folder you right-click, so with include/ and src/ you move the header by hand every time. Hedroot's own dialog puts each file in its folder when you press Create.

  • My new header goes to include/ and its source to src/ the first time, with the #include already right.
  • I see both paths before anything is written.
  • Each module gets its own folders, and my team shares the rules (license).

Free: one placement rule and the dialog, no time limit. $7 once, personal and commercial alike, adds a rule per module, CMake target lines where a target names its files, CLion's own New dialogs and shared rules; 30-day trial, nothing renews.

CLion already creates class files. New | C++ Class writes the header and the source together, in the folder you right-click. If your headers and sources share a folder, you do not need Hedroot. CLion's file templates also accept a relative path in their file name; that is not the New C++ Class dialog, and where the files land depends on the folder you start from.

How it works

Quick start

1. Set a rule (free)
A header folder and a source folder, relative to the folder the rule covers. {fmt} keeps headers in include/fmt and sources in src; the page shows the paths and the #include for a class name you type.

2. Create a class (free)
Right-click a folder, choose New | C++ Class (Header/Source Folders), and check the two paths in the dialog above; edit either for this class only. An existing file at either path stops it with both paths named and nothing written. A Remove link in the balloon after Create deletes both files until you edit one.

  • CLion's own New | C++ Class on {fmt}'s src, class Formatter: header src/formatter.h, source src/formatter.cc, with #include "formatter.h".
  • Hedroot, one rule: header include/fmt/formatter.h, source src/formatter.cc, with #include "fmt/formatter.h".

Headless run on an unmodified copy of {fmt} at commit 14ac0d5, CLion 2025.3, Hedroot 1.0.1, New File Extensions set to the .h/.cc pair with a lower-case naming convention. CLion's row is CLion's class code run in the same test, not a CLion window.

3. With a license: CMake target and a rule per module
The dialog lists the targets whose CMakeLists.txt names their files and says before Create which line it will change, or why it will leave the target alone. On {fmt} the only place a new file can go is inside if (FMT_OS), so Hedroot does not preselect it; you choose fmt in the list.

On twelve popular open-source libraries the studio tried (a rule of include/<name> and src), the CMake edit was right and unconditional on 2, offered only inside an if() on 1, refused with the reason on 8, and found no target on 1. A list built from a variable or file(GLOB), or a target made by a function or macro, is left unchanged and the dialog says why.

Also with a license

  • Namespace subfolders: net::tcp gives include/net/tcp and src/tcp.
  • CLion's own dialogs: switch on the move and files made by CLion's New C++ Class, C/C++ Header File, C/C++ Source File or New | File go to the rule's folders, with a Move back link. Off until you turn it on.
  • Team rules: Save my rules to the rules file writes .hedroot-rules; commit it. A teammate without a license gets its first rule.

The license is $7 once, the same for personal and commercial use, every update included, nothing renews; the 30-day trial of everything starts from the Get a license or trial link on the settings page and uses your JetBrains Account. After the trial the first rule keeps working and the others stay saved.

Limits

  • CLion 2025.3 or later. Not run on Windows or macOS.
  • Not run in a CLion window: Remove, Undo and the move of CLion's own files were tested headless, not by a keypress or a click in CLion.
  • CMake projects only for target updates; Makefile, Meson, Bazel, compilation-database and PlatformIO projects get placement only.
  • New files only: Hedroot does not move, rename or reorganise files that already exist. Folders must be inside the project.
  • Not in version one: C++20 module interface units, Rider and other JetBrains IDEs, Remote Development clients.
