Hedroot quick start

Your first rule and your first class. Back to the product page. None of these steps has been followed in a CLion window yet; they are checked against the plugin's code and tests (limits).

Install

Hedroot is not on JetBrains Marketplace yet, so there is nothing to install from there today. Once it is listed, in CLion 2025.3 or later:

  1. Open Settings | Plugins. Install Hedroot from the Marketplace tab, or choose the gear icon and Install Plugin from Disk... and pick the zip without unpacking it.
  2. Restart CLion when it asks.

After the restart CLion shows no sign of Hedroot beyond two places: the settings page Settings | Editor | Hedroot Header/Source Folders, and the entry New | C++ Class (Header/Source Folders), also reachable from Find Action.

Your first rule

  1. Open the settings page and press +.
  2. Fill in three fields, all relative to the folder the rule covers: Folder this rule covers (. is the project root), Header folder (for example include/fmt) and Source folder (for example src). Leave Include root (optional) empty unless the line under the fields names the wrong folder (the one your compiler's include path points at).
  3. Type a class name under Try a class. The page shows the two paths and the #include line the rule produces, and which folder the #include is relative to. A folder outside the project, or a header folder equal to the source folder, is refused in its field with the reason.
  4. Press OK.

Your first class

  1. Right-click a folder in the Project view, for example src, and choose New | C++ Class (Header/Source Folders).
  2. Type a name. The dialog shows both paths, for example include/fmt/formatter.h and src/formatter.cc, and the source's #include line. Edit either path for this class only.
  3. Press Create. Both files open in their folders and one balloon appears with a Remove link.

Nothing changed, or both files in one folder? The entry you used must be Hedroot's, not CLion's own New | C++ Class, and the rule's folder must contain the folder you right-clicked. With no rule covering the folder the dialog says so and writes nothing. The file type follows Settings | Editor | Code Style | C/C++ | New File Extensions, and the include guard follows the Header guard style on the Naming tab of that page.

With a license

Each of these needs a license or the 30-day trial.

  • A rule per module. Add a rule for each folder; the rule whose folder most closely encloses the folder you right-click applies.
  • Namespace subfolders. With the option on, a class Socket in net::tcp under headers include/net and sources src goes to include/net/tcp/socket.h and src/tcp/socket.cpp. Names the header folder already ends with are not repeated.
  • CMake target. Choose the target in the same dialog; the line under it names the file and line Hedroot will change, or says why it will leave the target alone (a list built from a variable or file(GLOB), a target made by a function or macro, sources split across if() blocks).
  • Move CLion's own files. Switch on Move files created by CLion's New dialogs into the rule's folders on the settings page. A balloon after CLion's own New C++ Class names where the files went, with Move back.
  • Team rules. Save my rules to the rules file writes .hedroot-rules at the project root. Commit it; a change that arrives with a Git pull applies without a restart.

License and trial

The free part works at once and nothing pops up. A license is $7 once, the same for personal and commercial use, every update included, nothing renews, with a 30-day trial of every feature. The Get a license or trial link on the settings page and in the dialog opens the IDE's license dialog; choose Hedroot there and start the trial. Starting a trial or buying uses your JetBrains Account. When the trial ends, the first rule keeps working and the others stay saved.

The license is checked through JetBrains Marketplace licensing. The trial and the purchase can start only once Hedroot is on the Marketplace; they have not been run.

Limits

  • CLion 2025.3 or later. Not run on Windows or macOS, and not run in a CLion window.
  • CMake projects only for target updates. Makefile, Meson, Bazel, compilation-database and PlatformIO projects get placement only.
  • New files only: Hedroot does not move, rename or reorganise files that already exist.
  • Folders must be inside the project.
  • The #include is relative to an include folder that Hedroot works out from your folder names; it does not read your CMake include directories, so set the Include root on the rule if it guesses wrong.
  • Not in version one: C++20 module interface units, Rider and other JetBrains IDEs, Remote Development clients, keeping namespace, folder and file names in sync.

Privacy

Hedroot reads the names of folders in the open project, its CMakeLists.txt files and its rules file. It makes no network calls and sends nothing (privacy policy).
