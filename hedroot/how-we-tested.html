How we tested Hedroot

Back to the product page. Everything here is Hedroot 1.0.1 and ran on Linux.

  • 189 automated tests in 22 classes, none failing, run without a display in CLion 2025.3, and 18 more acceptance tests written separately from them, none failing.
  • Plugin Verifier 1.411: compatible with CLion 2025.3 and CLion 2026.3.0.1, no internal, experimental or deprecated API used. A headless start of each CLion with the plugin installed loads it with no error. CLion 2026.3 is not covered by the test suite.
  • 4 builds with real CMake after Hedroot's edits (a PUBLIC section after PRIVATE sources, an INTERFACE section, and a target defined in both branches of if()/else() with the option on and off): the new source was compiled exactly once, for the library, in each. The new source goes into the PRIVATE section, never PUBLIC or INTERFACE.
  • On twelve popular open-source libraries (a rule of include/<name> and src, the dialog started in the library's source folder), the CMake edit was right and unconditional on 2, offered only inside an if() on 1, refused with the reason on 8, and found no target on 1. A list built from a variable or file(GLOB), or a target made by a function or macro, is left unchanged and the dialog says why.
  • Speed on {fmt} (10 CMakeLists.txt files), CLion 2025.3 headless, a 4-core 2.3 GHz Xeon, median of 10 runs: Create to both files open 39 ms, worst 115 ms.
  • The {fmt} comparison on the product page was run headless on an unmodified copy of {fmt} at commit 14ac0d5, CLion 2025.3, with New File Extensions set to the .h/.cc pair and a lower-case naming convention. CLion's row is CLion's own class code run in the same test, not a CLion window. With fmt chosen in the target list, Hedroot changed one file, CMakeLists.txt, line 305.
  • Not run: a CLion window (Remove, Undo and the move of CLion's own files were tested by CLion's undo manager and by playing back CLion's own events), Windows, macOS, and the Marketplace trial and purchase.
  • The pictures are Hedroot's own screens, drawn by CLion 2025.3's interface toolkit in a test window on unmodified copies of {fmt} (commit 14ac0d5) and rclcpp (commit 9e66d4d), in the dark theme. They are not captures of CLion's own window: CLion's release builds ask for a JetBrains Account login before they can be used, and the test machine has none; the early-access build of CLion 2026.3 that needs no login had expired. The pictures of paid features were taken with the license check switched on by a test tool.
  • The film shows the same screens, unlicensed, recorded one frame at a time with real mouse and key events and put together at 60 frames a second, with the real pointer and a slow push-in on each scene (the interface itself rests while a caption is read). The class is called Writer because {fmt} already has files called format, and typing Formatter passes through that name; the last scene shows that refusal. The header guard's project part is set so that it reads as it would in a project named fmt. The film does not show CLion's own New dialogs, its Project view or a CLion window.
